# AI 协议（AI_PROTOCOL v0，预留位）

> 2026-11-22 立。**这份文档先于实现存在**：先把契约写死，接模型时只填实现，不改结构。
> 当前代码里 AI 层是空实现（`ai/provider.py` 的 `NullProvider`），程序不依赖它。

## 1. 边界（不可越线）

```dsh-ui
{"title":"AI 能做什么","items":[{"type":"table","columns":["能做","不能做"],"rows":[["在候选里挑出最贴合用户问法的一条","生成知识条目"],["判断这句话是否有歧义","修改代码正文"],["给出用户意图的一句话概括","返回候选集合之外的 ID"],["建议相关的其他候选","凭记忆编造 API"]]}]}
```

**一句话：AI 只整理事实，不生产事实。**

## 2. 请求（发给模型的内容）

只发候选摘要，**不发代码正文**——省 token，也避免模型照着改代码。

```json
{
  "query": "判断文件后缀",
  "candidates": [
    {
      "entry_id": "py.fs.check_extension",
      "title": "判断文件后缀",
      "description": "只看文件名后缀，判断是不是某一种格式",
      "object_name": "文件后缀",
      "action_name": "判断",
      "aliases": ["后缀", "扩展名", "suffix"]
    }
  ]
}
```

## 3. 响应（要求模型输出）

```json
{
  "intent": "根据文件名判断是不是某种格式",
  "primary_entry_id": "py.fs.check_extension",
  "related_entry_ids": ["py.fs.get_extension"],
  "ambiguous": false
}
```

## 4. 校验规则（程序侧，必须全过）

| 检查 | 不过怎么办 |
|---|---|
| 是合法 JSON | 丢弃 AI 结果，用本地排序 |
| `primary_entry_id` 在**本次候选集合**里 | 同上 |
| `related_entry_ids` 每个都在候选集合里 | 同上 |
| `related_entry_ids` 数量 ≤ 5 | 同上 |
| `intent` 是字符串且长度 ≤ 100 | 退化：清空 intent，保留排序 |

**不做“部分采纳”。** 一条不合法就整份退回本地结果——半信半疑的组合比单纯用本地结果更难排查。

## 5. 缓存

```
key   = 查询原文 + 候选 id 列表的哈希 + 模型标识
value = 校验通过的响应
```

- 缓存独立存放（`data/cache/`），可单独清空；
- 模型换了、候选变了，key 就变，不会读到过期结果。

## 6. 故障降级

| 情况 | 行为 |
|---|---|
| 没有 API key | 用 `NullProvider`，本地排序 |
| 请求超时 | 等不到就退回本地排序，界面提示“本次未使用 AI 整理” |
| 返回不是 JSON | 丢弃，退回本地排序 |
| 返回了不存在的 ID | 丢弃，退回本地排序 |
| 候选为空 | 不调用模型（省一次请求） |

## 7. 前端预留位

- 设置里一个开关：`ai.enabled`（**默认关**，免得莫名花额度）；
- 结果页上方一块区域：显示 `intent`（“我理解你要的是…”）；
- 若 `organized_by == "local"`，这块显示“本地结果”，不假装是 AI 排的。
